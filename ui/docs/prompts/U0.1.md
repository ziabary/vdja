# 3. Correction 1 — Follow-up Ownership

The U0 migration contract currently selects:

```text
Authenticated User Dashboard
→ CRM customer review
→ create one follow-up task
→ smart summary
```

This is a valid migration slice, but target domain ownership must be explicit.

The target architecture already defines **Follow-up as an independent business module**.

Update `docs/ui/04-migration-contract.md` and any affected reconciliation/architecture wording so that it explicitly states:

```text
The follow-up/task step in the first vertical slice does not make CRM
the canonical owner of generic follow-up semantics.

Target ownership of generic actionable follow-up tasks, deadlines,
reminders and follow-up lifecycle belongs to the Follow-up module.

CRM owns the customer/business context and consumes Follow-up through
its published contract / ResourceRef integration.

Any legacy CRM-local task implementation used during migration is a
temporary compatibility boundary only.

It must not become the target Follow-up domain model.
```

Also distinguish, where necessary:

```text
CRM-specific internal activity
vs
generic Follow-up task
```

If a task is genuinely CRM-specific, say so explicitly.

Do not silently move Follow-up semantics into CRM.

# 4. Correction 2 — SSR Bootstrap Is Not Refresh-Token Scope Expansion

The current target UI architecture correctly identifies that the existing refresh cookie has:

```text
Path=/api/
```

and therefore is unavailable to ordinary SvelteKit page SSR requests.

However, wording must not imply that Web may simply widen the existing refresh-token cookie to:

```text
Path=/
```

for convenience.

Update `docs/ui/03-target-ui-architecture.md` and reconciliation text where appropriate.

Canonical rule:

```text
Do not widen the refresh-token cookie from Path=/api/ to Path=/
merely to enable authenticated SSR.
```

If SSR requires a host-scoped browser credential, it must be a separately designed Identity-owned mechanism, for example:

```text
opaque SSR/session-bootstrap credential
or
Identity-owned session introspection/bootstrap contract
```

Requirements:

- Identity owns credential semantics.
- Web owns only the need for authenticated SSR bootstrap.
- Web does not invent authentication authority.
- Refresh-token scope remains an Identity/security decision.
- SSR bootstrap credential must not expose refresh-token material.
- No token is serialized into page data.
- Browser-visible load data contains only safe session/tenant/capability views.
- CSRF, SameSite, Origin, Secure and rotation/revocation behavior belong to the Identity contract.
- U1 may implement interfaces/fakes only; no production cookie change is authorized by U0/U1.

Replace wording equivalent to:

```text
backend must implement a Path=/ credential
```

with wording that preserves the need while leaving credential design to Identity.
