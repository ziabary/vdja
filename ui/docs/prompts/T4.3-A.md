6. NOT_APPLICABLE RULE
============================================================

NOT_APPLICABLE is permitted only when the technical feature or condition
described by that specific requirement does not exist in the current product
or deployment model.

Examples that MUST be investigated for likely N/A classification include,
but are not automatically N/A:

OAuth/OIDC-specific requirements
WebRTC-specific requirements
GraphQL-specific requirements
WebSocket-specific requirements
LDAP/JNDI-specific requirements
LaTeX-specific requirements
SOAP/XML-specific requirements
client-side cryptography-specific requirements
biometric/TOTP/SMS requirements where those mechanisms are not supported

For each N/A result include an explicit statement such as:

"The current target product exposes no GraphQL endpoint and imports/uses no
GraphQL server/client runtime. Repository inspection and route inventory
confirm this requirement has no applicable execution path."

Do not use:

"Feature not implemented"

as the sole reason.
