# ارزیابی مهندسی OWASP ASVS 5.0.0 سطح ۳

**وضعیت: ناقص / PARTIAL.** این ارزیابی گواهی ASVS یا تکمیل T4 نیست. دروازهٔ شروع T5 از دروازهٔ انتشار مشتری مستقل است.

منبع رسمی: [فایل تخت ASVS 5.0.0](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.flat.json)، SHA-256: `8201b20eec2908c3380ac600c91c8ba746346fbb808859366abb232027532311`.

شاهد canonical: `reports/security/asvs-5.0-l3.json`. شرح فارسی و نتیجهٔ جداگانه برای همهٔ ۳۴۵ کنترل ثبت شده است: **72 PASS، 17 FAIL، 100 N/A، 156 NOT_VERIFIED**. در T4.4-C، فقط الزاماتی که شواهد production فعلی و آزمون زنده آن‌ها را کامل اثبات کردند به PASS تغییر یافتند: V8.2.2، V8.2.3، V8.3.3، V5.2.5، V5.3.3، V3.4.4 و V16.3.2. دیگر شکست‌های پیشین، از جمله V6.2.2، V6.2.4، V6.3.3، V6.3.5 و V6.4.3 باز مانده‌اند.

## دامنه و روش

محصول هدف شامل Web/SvelteKit، API، Worker، PostgreSQL، CJSON، secrets، تصویر مشتری، AI Router، SIEM، ابزارهای عمومی، فایل/streaming، هویت/نشست/Authority و زنجیرهٔ تأمین است. موجودی ماشین‌خوان مسیر/پروتکل/رمزنگاری و runtime در `reports/security/t4-target-scope-inventory.json` قرار دارد. ماتریس فصل‌ها، دلیل هر N/A و backlog کامل در `docs/security/04-t4-asvs-applicability-matrix-fa.md` آمده است. نتیجهٔ PASS فقط به شاهد کد/آزمون/تصویر مشخص تکیه دارد؛ نبود شاهد برای کنترل قابل‌اعمال به NOT_VERIFIED منجر شده است. این بازبینی آزمون نفوذ بیرونی نیست.

## شواهد اثبات‌شده

مسیر target برای HUMAN سه ابزار Translator، Summarizer و FAQ را با Session، Authority و Admission اجرا می‌کند؛ Usage، Audit و Security Telemetry/SIEM در آزمون PostgreSQL/HTTP زنده بررسی شده‌اند. آزمون Chrome رفتار ورود، انتخاب مستأجر، حافظه‌ای بودن access token و کوکی Refresh را بررسی کرده است. password scrypt، guard پایدار ورود، JWT امضاشده Ed25519، اعتبارسنجی issuer/audience/kid و زمان، چرخش Refresh و رد replay، CORS/Origin دقیق، SQL پارامتری، محدودیت بارگذاری/مصرف و خطای امن شواهد PASS مختص خود دارند. این شواهد مجوزدهی عمومی همهٔ منابع یا همهٔ شرایط استقرار مشتری را ثابت نمی‌کنند.

## نقص‌ها و مرز شواهد

17 FAIL شامل جداسازی میزبان Auth در استقرار واقعی مشتری، نام فایل در همهٔ پاسخ‌های دانلود، قواعد گذرواژه/نشست و WebAuthn است. V16.3.2 برای تمام مصرف‌کنندگان Authority در production فعلی با ممیزی فراخوانی‌ها، آزمون ALLOW/DENY و قاعدهٔ ایستای معماری PASS شد؛ مصرف‌کنندگان آیندهٔ T5 به ارزیابی تازه نیاز دارند. پیش‌بررسی DOCX/ODT و پاک‌سازی نام نمایشی FAQ پیاده شده‌اند، اما پوشش کل الزام نام فایل هنوز ثابت نشده است. سیاست واژه‌های زمینه‌ای و بررسی گذرواژهٔ افشاشده آزمون واحد دارند، ولی مسیر عملیاتی تغییر/بازیابی گذرواژه ندارند؛ وضعیت این کنترل‌ها FAIL می‌ماند. 156 مورد برای آزمون یا بازبینی اختصاصی باز است؛ از جمله TLS edge، HSTS/سرآیندهای تولید، HSM و نگهداشت کلید، redaction و مقصدهای همهٔ لاگ‌ها، SBOM تصویر فعلی و اسکن وابستگی. قفل runtime ۱۰۳ مدخل registry با integrity دارد و تصویر پایه digest-pinned است، اما این به‌تنهایی اثبات نبود dependency confusion یا آسیب‌پذیری شناخته‌شده نیست. SBOM نسخهٔ 1.0.1 دامنهٔ build/root وسیع‌تری دارد و جای SBOM تصویر تازه را نمی‌گیرد. `npm audit` شاهد قابل‌قبول تولید نکرد؛ ارسال فراداده به npm registry در بازبینی خودکار مجوز رد شد.

## تصمیم انتشار

T4 = PARTIAL؛ `RAG_SECURITY_GATE = YES` برای شروع T5 پس از اجرای موفق همهٔ آزمون‌های بنیاد؛ `ASVS_L3_RELEASE_GATE = NO`. 173 کنترل قابل‌اعمال باز مانده‌اند. هیچ کنترل با صرف نبود قابلیت آینده PASS نشده است.
