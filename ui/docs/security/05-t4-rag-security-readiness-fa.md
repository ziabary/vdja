# گزارش آمادگی امنیتی شروع T5 — T4.4-C

## دامنه و وضعیت

`RAG_SECURITY_GATE` همان `T5_START_GATE` است و فقط اجازهٔ آغاز پیاده‌سازی
Document، File Management و RAG را تعیین می‌کند. `T5_COMPLETION_SECURITY_GATE`
بعد از پیاده‌سازی T5 ارزیابی می‌شود. `ASVS_L3_RELEASE_GATE` مستقل است و تا
بسته‌شدن تمام کنترل‌های قابل‌اعمال باز، انتشار مشتری را مسدود می‌کند.

ماتریس مرجع `reports/security/asvs-5.0-l3.json` اکنون ۷۲ PASS، ۱۷ FAIL،
۱۵۶ NOT_VERIFIED و ۱۰۰ N/A دارد. ۱۷۳ کنترل باز باقی مانده‌اند. فایل
`reports/security/rag-asvs-classification.json` برای هر کنترل باز سه بُعد
مستقل `blocksT5Start`، `verifyDuringT5` و `blocksCustomerRelease` را به
همراه دلیل، مالک، شاهد و فاز لازم ثبت می‌کند. شمار فعلی: صفر مانع شروع T5،
۱۰۲ کنترل برای راستی‌آزمایی در T5، و ۱۷۳ مانع انتشار مشتری. از ۱۷۳ مورد،
۷۱ کنترل در backlog ویژهٔ T5 نیستند و باید پیش از انتشار مشتری بسته شوند.
هیچ کنترل موکول‌شده PASS نامیده نشده است.

## بنیادهای الزامی پیش از T5

دروازهٔ ماشینی `reports/security/rag-security-gate.json` آزمون‌های هویت و
نشست، جداسازی مستأجر، قرارداد ۳۹/۳۹ Authority، حل مجوز از PostgreSQL، مجوز
شیء و میدان، ACL، طبقه‌بندی/سطح دسترسی، مالکیت/دامنه، زمان‌بندی و ابطال نسخهٔ
مجوز، حفظ هویت آغازگر HUMAN، Audit اجباری هر تصمیم، دوام Audit→SIEM،
تغییرناپذیری و پاک‌سازی Audit، پیکربندی/secretRef، مالکیت SQL و AI Router،
ایمنی File Processing فعلی و قواعد ایستای معماری را اجرا می‌کند. یافتهٔ
معماری هدف باید صفر باشد.

ممیزی تمام فراخوانی‌های Authority در target فعلی در
`docs/security/07-t4-authority-decision-boundary.md` ثبت شده است: تنها مصرف‌کنندهٔ
بیرونی production، مسیر ابزار عمومی API، سرویس canonical را فرا می‌خواند؛
فراخوانی‌های pure evaluator درون Authority یا آزمون هستند؛ bypass تولیدی صفر
است. آزمون زنده ALLOW و DENY، شکست بسته هنگام خرابی Audit برای ابزار عمومی،
شیء، میدان، ACL و طبقه‌بندی، و ارسال SIEM بدون محتوای حفاظت‌شده را بررسی
می‌کند. `ARCH-AUTH-004` ورود مستقیم evaluator به مصرف‌کنندهٔ تولیدی را رد
می‌کند. بر این شواهد، V16.3.2 برای دامنهٔ production فعلی PASS است؛ مصرف‌کنندهٔ
جدید T5 باید دوباره بررسی شود.

ایمنی فعلی File Processing شامل سازگاری پسوند/نوع/امضا، سقف اندازه و شمار
ورودی آرشیو و نسبت فشرده‌سازی، رد پیمایش مسیر و پیوند نمادین، timeout
parser، پاک‌سازی موقت و مسیر داخلی امن است. رفتار بارگذاری و دانلود File
Management، S3، Content-Disposition، URL امضاشده و cache هنوز وجود ندارد و
در همین فاز الزامی است.

## کنترل‌های درون T5

`reports/security/t5-security-delta-backlog.json` هر ۱۰۲ کنترل را با الزام،
قابلیت، شاهد لازم، آزمون مورد انتظار و اثر انتشار نگه می‌دارد. این موارد
شامل ورودی/خروجی و نمایش RAG، چرخهٔ Document/File Management، Web/API جدید،
مجوز انتقال و سند، S3 و خروج داده، حفاظت دادهٔ سند، محدودیت منابع و ثبت و
بازیابی T5 هستند. `docs/prompts/T5-addendum.md` برای File Management مشترک،
Local/S3، نسخه، انتقال/cache امن، Authority، Admission، Usage، Audit و SIEM
الزامی است. `docs/security/06-t5-genai-rag-security-gate.md` آزمون‌های تزریق
پرامپت، آلودگی بازیابی، جداسازی مستأجر/بردار، مجوز پیش از materialization،
افشای داده، خروجی ناامن، egress، آلودگی context و مصرف منابع را درون/پس از
T5 الزامی می‌کند.

## کنترل‌های انتشار مشتری

هر ۱۷۳ کنترل باز هنوز مانع Level 3 است. ۷۱ مورد که به سطح تازهٔ T5 نیاز
ندارند، شامل چرخهٔ احراز هویت، MFA سخت‌افزاری، بازیابی گذرواژه، مدیریت نشست
مشتری، DNS/TLS/HSTS، HSM، برخی استقرار و زنجیرهٔ تأمین و شاهد عملیاتی هستند.
آن‌ها از دروازهٔ شروع T5 حذف نشده‌اند؛ در دروازهٔ مستقل انتشار باقی‌اند.
نشست گذرواژه فقط برای `DEVELOPMENT_PASSWORD` در توسعه/آزمون مجاز است و
`CUSTOMER_L3` همچنان مسدود می‌ماند.

## تصمیم

اگر تمام آزمون‌های بنیاد در اجرای فعلی گزارش ماشینی PASS بمانند،
`RAG_SECURITY_GATE = YES` و شروع T5 مجاز است. کنترل باز PRE-T5 فعلی صفر است.
`ASVS_L3_RELEASE_GATE = NO`، T4 = PARTIAL، و انتشار مشتری مجاز نیست.
این تصمیم به معنای تکمیل یا آغاز اجرای T5 نیست.
