# T4 authenticated public services: current implementation

Translator, Summarizer and FAQ accept anonymous calls and authenticated HUMAN calls. The browser holds the access token in component memory and forwards it with the selected tenant through the Web gateway. The API validates the signed access token against the canonical PostgreSQL session, identity, membership and authorization version before resolving Authority facts. Authority reads tenant-scoped grants under PostgreSQL RLS and invokes the production pure decision kernel. A missing, invalid, cross-tenant or denied grant fails closed before Admission or AI Router.

The registered Authority vocabulary is `PublicTools.<module>.use` plus a STRING `PublicTools.<module>.limitTier`. A grant must allow `use` and carry `AUTHENTICATED` or `PRIVILEGED` on an active grant for that module. Explicit deny takes precedence; root `ALL` cannot override a token tenant mismatch. Configuration supplies anonymous, authenticated and privileged policies. Each policy includes input characters, upload bytes, output tokens, requests per minute, concurrency, daily requests, daily input characters and daily token budget. Parser and upload hard ceilings remain in File Processing and platform Configuration. Admission Control makes the request-size, output-budget, rate, concurrency and quota decision. Extracted FAQ/file text is reported to Admission before AI execution so its size and daily quota are checked. Modules receive the effective policy; they do not interpret login state.

The live `t4-authenticated-public.integration.test.ts` fixture creates Tenant A, Tenant B, User A, User B and a user belonging to both. It runs anonymous and authenticated Translator, Summarizer and FAQ requests through a local fake AI provider. It checks explicit tenant choice, non-merged grants, explicit deny, root ALL tenant boundary, PostgreSQL RLS, N−1/N/N+1 input/upload/output limit boundaries, and absence of provider calls on input denial. HUMAN Usage records actor and session IDs; semantic Audit and SIEM export preserve actor, session, tenant, module, request and correlation IDs. `scripts/t4-gate.mjs` runs this fixture as an executable integration gate and requires explicit live PostgreSQL configuration.

Chrome coverage now checks branded login, tenant selection, memory-only access tokens, refresh cookie, refresh/replay, logout, Auth-disabled UI, a secure `__Host-` preference cookie, and authenticated use of all three tools with a mocked backend. A separate customer C API image passed the live three-tool fixture with MySQL stopped.
