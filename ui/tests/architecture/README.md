# T1 static architecture guardrails

Run `npm run test:architecture` for every static category and `npm run test:guardrails` for static checks plus Authority behavioral conformance. Category scripts in `package.json` can run independently. Each command returns nonzero for architecture violations; the runners continue through all suites. `tests/reports/architecture-violations.json` is deterministic and contains the canonical sorted violations, counts, and run scope.

`support/staticAnalysis.ts` owns the rule catalog and executable checks. It walks first-party `src`, `db`, `apps`, `packages`, and `modules` TypeScript/SQL while excluding generated/vendor/build/test files. TypeScript Compiler API handles imports, declarations, calls, and expressions. SQL source patterns cover only high-confidence statements. No baseline or grandfathered file list suppresses legacy findings. A zero count means no matching source was found, not that a rule is inactive; fixture tests exercise representative detectors. `test:architecture` runs those self-tests before every category; a self-test failure is reported separately as `TEST_INFRA_FAILURE`.

The explicit ORM deny list is `typeorm`, `sequelize`, `prisma`, `@prisma/client`, `@mikro-orm/core`, `mikro-orm`, `drizzle-orm`, and `objection`. Kysely is allowed as a query builder. DB naming checks use the table prefix examples explicitly registered in the architecture (`usr`, `grp`, `tkt`, `vch`); for other tables they only reject obvious generic column names. The complete table-prefix registry has no static canonical source yet, so broader column-prefix proof is partial. SQL checks recognize straightforward PostgreSQL DDL/DML and SQL literals in query/raw/execute calls or `sql` templates. Arbitrary TypeScript text is not parsed as SQL. Dynamic SQL, computed identifiers, vendor-specific quoted syntax, and procedural language constructs beyond simple `DECLARE` blocks need later parser/behavioral coverage. Recognized legacy MySQL dumps are not treated as target PostgreSQL migrations for schema-qualification checks; this is a dialect distinction, not a file baseline. Rule `ARCH-TS-004` is deliberately conservative about dictionaries in public contracts. AI-output-to-persistence flow detection is a direct-call heuristic and does not claim whole-program data flow.

The database boundary classifier separates Platform persistence, external source adapters, composition roots, transport, application, and workers. External database driver imports are allowed only in approved integrations/Secretariat database adapter locations. Generic `db.query`, Platform repository imports, and SQL naming an authoritative Platform object remain forbidden there; explicitly source-named client calls are treated as external reads. Inbound source write SQL is reported. An outbound adapter can issue write SQL only when its location is an `outbound` adapter and it imports the explicit `intfExternalDatabaseOutboundPort` or `intfSourceDatabaseOutboundConnector` contract. Composition roots may import repository factories for wiring but may not execute SQL or repository queries. These static signals do not prove the connection string, Data Governance approval, or runtime read-only privileges; those require contract/integration enforcement.

Typed manifests use `modules/<module>/manifest.ts`. AST inspection requires an exported canonical `MODULE_MANIFEST` or `manifest` object with an explicit `intfModuleManifest`/`typModuleManifest` annotation or `satisfies` clause. It checks required fields, optional contribution shape, and static IDs from that declaration only. Route method/path collisions are scoped to the owning module and surface; canonical route contribution IDs remain global. It does not execute manifest code. Computed IDs require a future contract-aware compiler evaluation and are not silently treated as validated. Missing manifests are `TARGET_NOT_IMPLEMENTED`.

The magic-decision check targets stable business/security state names. Generic formatting discriminators such as PDF `kind`/`type` are not treated as business decisions. Exported stable primitive constants are checked for UPPER_SNAKE_CASE; ordinary local `const` bindings remain camelCase. These are deliberately high-confidence heuristics.

Authority conformance is defined in `tests/conformance/authority/authorityBehavior.test.ts`. A test-side module named by `AUTHORITY_CONFORMANCE_ADAPTER` exports `authorityConformanceAdapter`; the suite never assumes Express, JWT, PostgreSQL, or a class layout. With no target binding, each encoded behavior fails with `TARGET_AUTHORITY_ADAPTER_NOT_AVAILABLE`. The adapter exposes pure evaluation, typed value lookup, and revocation/invalidation contract information. It does not fake session persistence.

## T2: live PostgreSQL conformance
